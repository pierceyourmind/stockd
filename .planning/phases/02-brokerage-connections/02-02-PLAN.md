**1. plaidCreateLinkToken(PDO $pdo)**

Creates a link_token for initializing Plaid Link on the frontend. Called via GET by the frontend before opening the Link widget.

```php
function plaidCreateLinkToken(PDO $pdo): never {
    try {
        $plaid = getPlaidClient();
        $appUrl = $_ENV['APP_URL'] ?? '';
        $redirectUri = $appUrl . '/auth/plaid_callback.php';

        $user = new \TomorrowIdeas\Plaid\Entities\User('stockd-user');

        $token = $plaid->tokens->create(
            'Stockd Portfolio Tracker',  // client_name
            'en',                         // language
            ['US'],                       // country_codes
            $user,                        // user
            ['investments'],              // products
            $redirectUri                  // redirect_uri (for OAuth institutions like Schwab)
        );

        jsonResponse(['link_token' => $token->link_token]);
    } catch (\Exception $e) {
        error_log('plaidCreateLinkToken error: ' . $e->getMessage());
        jsonResponse(['error' => 'Failed to create link token: ' . $e->getMessage()], 500);
    }
}
```

Key notes:
- The `User` entity requires a unique user ID string. Use a fixed 'stockd-user' since this is a single-user app (same pattern as the old SnapTrade single-user approach).
- Products MUST include 'investments' to get investment account data.
- The redirect_uri is required for OAuth-based institutions (Schwab uses OAuth). It must match a URI registered in the Plaid Dashboard.
- The SDK constructor signature for `tokens->create()` uses positional args. Check the SDK source if named params are available. The community SDK may use a different call pattern -- if `create()` doesn't accept positional args, try passing an associative array or using the request builder pattern. Adapt as needed but the key parameters are: client_name, language, country_codes, user, products, redirect_uri.

**2. plaidExchangeToken(PDO $pdo)**

Exchanges a public_token (from Plaid Link onSuccess) for a persistent access_token. Called via POST with JSON body `{ "public_token": "...", "institution": { "institution_id": "...", "name": "..." } }`.

```php
function plaidExchangeToken(PDO $pdo): never {
    $input = json_decode(file_get_contents('php://input'), true);
    $publicToken = $input['public_token'] ?? '';
    $institutionId = $input['institution']['institution_id'] ?? null;
    $institutionName = $input['institution']['name'] ?? null;

    if (empty($publicToken)) {
        jsonResponse(['error' => 'public_token is required'], 400);
    }

    try {
        $plaid = getPlaidClient();

        // Exchange public_token for access_token
        $response = $plaid->items->exchangeToken($publicToken);
        $accessToken = $response->access_token;
        $itemId = $response->item_id;

        // Encrypt access token before storage
        $encryptedToken = encryptAccessToken($accessToken);

        // Store the item
        $stmt = $pdo->prepare("
            INSERT INTO plaid_items (item_id, institution_id, institution_name, access_token_encrypted)
            VALUES (?, ?, ?, ?)
            ON CONFLICT(item_id) DO UPDATE SET
                access_token_encrypted = excluded.access_token_encrypted,
                institution_name = excluded.institution_name,
                status = 'active',
                updated_at = CURRENT_TIMESTAMP
        ");
        $stmt->execute([$itemId, $institutionId, $institutionName, $encryptedToken]);

        // Fetch and store accounts for this item
        $accountsResponse = $plaid->accounts->list($accessToken);
        $plaidItemDbId = $pdo->lastInsertId();

        // If this was an UPDATE (not INSERT), get the existing ID
        if (!$plaidItemDbId) {
            $idStmt = $pdo->prepare("SELECT id FROM plaid_items WHERE item_id = ?");
            $idStmt->execute([$itemId]);
            $plaidItemDbId = $idStmt->fetchColumn();
        }

        foreach ($accountsResponse->accounts as $account) {
            $stmt = $pdo->prepare("
                INSERT INTO plaid_accounts (plaid_item_id, account_id, name, official_name, type, subtype, mask, balance_current, balance_available)
                VALUES (?, ?, ?, ?, ?, ?, ?, ?, ?)
                ON CONFLICT(account_id) DO UPDATE SET
                    name = excluded.name,
                    official_name = excluded.official_name,
                    type = excluded.type,
                    subtype = excluded.subtype,
                    balance_current = excluded.balance_current,
                    balance_available = excluded.balance_available,
                    updated_at = CURRENT_TIMESTAMP
            ");
            $stmt->execute([
                $plaidItemDbId,
                $account->account_id,
                $account->name,
                $account->official_name ?? null,
                $account->type,
                $account->subtype,
                $account->mask ?? null,
                $account->balances->current ?? null,
                $account->balances->available ?? null,
            ]);
        }

        jsonResponse(['success' => true, 'item_id' => $itemId]);
    } catch (\Exception $e) {
        error_log('plaidExchangeToken error: ' . $e->getMessage());
        jsonResponse(['error' => 'Failed to exchange token: ' . $e->getMessage()], 500);
    }
}
```

Key notes:
- The SDK may return response objects with properties (->access_token) or arrays. Check the actual SDK return type and adapt. The community SDK typically returns objects.
- Use `ON CONFLICT ... DO UPDATE` for idempotent re-connections (user reconnects same institution).
- After storing the item, immediately fetch accounts so the UI has data right away.
- The `accounts->list()` method may be named differently in the SDK. Check for `accounts->getAccounts()` or similar. The raw Plaid endpoint is `/accounts/get` which takes an access_token. Find the correct SDK method by checking the SDK's Accounts resource.
- Account properties: account_id, name, official_name, type (investment/depository), subtype (401k, ira, roth, brokerage), mask (last 4 digits), balances.current, balances.available.
- IMPORTANT: The SDK response properties may use camelCase (accountId) instead of snake_case (account_id). Check the actual response format from the SDK and adapt property access accordingly.

**3. plaidConnections(PDO $pdo)**

Lists all connected Plaid items (brokerage connections) with their status.

```php
function plaidConnections(PDO $pdo): never {
    $stmt = $pdo->query("
        SELECT
            pi.id,
            pi.item_id,
            pi.institution_id,
            pi.institution_name,
            pi.status,
            pi.error_code,
            pi.created_at,
            pi.updated_at,
            COUNT(pa.id) as account_count
        FROM plaid_items pi
        LEFT JOIN plaid_accounts pa ON pa.plaid_item_id = pi.id
        GROUP BY pi.id
        ORDER BY pi.created_at DESC
    ");
    $connections = $stmt->fetchAll();

    jsonResponse(['connections' => $connections]);
}
```

**4. plaidAccounts(PDO $pdo)**

Lists all sub-accounts with their parent institution info.

```php
function plaidAccounts(PDO $pdo): never {
    $stmt = $pdo->query("
        SELECT
            pa.id,
            pa.account_id,
            pa.name,
            pa.official_name,
            pa.type,
            pa.subtype,
            pa.mask,
            pa.balance_current,
            pa.balance_available,
            pa.status,
            pa.created_at,
            pa.updated_at,
            pi.institution_name,
            pi.item_id as plaid_item_id
        FROM plaid_accounts pa
        JOIN plaid_items pi ON pa.plaid_item_id = pi.id
        ORDER BY pi.institution_name, pa.name
    ");
    $accounts = $stmt->fetchAll();

    jsonResponse(['accounts' => $accounts]);
}
```

Create `auth/plaid_callback.php` -- the OAuth redirect URI for Plaid Link. This is required for OAuth-based institutions like Schwab.

Unlike SnapTrade's callback (which did server-side processing), Plaid's OAuth callback is a mostly-blank page. Plaid Link handles the OAuth completion automatically on the client side. The page just needs to:

1. Include the Plaid Link JavaScript SDK
2. Exist at the registered redirect URI (HTTPS in production)
3. For desktop web, Link handles everything automatically
4. For mobile web, the page may need to reinitialize Link

Create `auth/plaid_callback.php`:

```php
<?php
declare(strict_types=1);
require_once __DIR__ . '/../bootstrap.php';
require_once __DIR__ . '/session.php';
requireAuth();
?>
<!DOCTYPE html>
<html lang="en">
<head>
    <meta charset="UTF-8">
    <meta name="viewport" content="width=device-width, initial-scale=1.0">
    <title>Connecting your account...</title>
    <link rel="stylesheet" href="https://cdn.jsdelivr.net/npm/@picocss/pico@2/css/pico.min.css">
    <style>
        body { display: flex; justify-content: center; align-items: center; min-height: 100vh; margin: 0; }
        .connecting { text-align: center; opacity: 0.7; }
    </style>
</head>
<body>
    <div class="connecting">
        <p aria-busy="true">Completing connection...</p>
    </div>
    <script src="https://cdn.plaid.com/link/v2/stable/link-initialize.js"></script>
    <script>
        // For OAuth redirect flows, Plaid Link handles completion automatically
        // on desktop browsers. This page serves as the registered redirect URI.
        // After Link processes the OAuth result, the onSuccess/onExit callbacks
        // from the original Link initialization will fire on the opener page.

        // If we landed here directly (e.g., mobile flow without an opener),
        // redirect back to the main app after a brief delay
        setTimeout(function() {
            if (window.opener) {
                // Desktop: opener page handles everything, just close this tab
                window.close();
            } else {
                // Mobile/direct: redirect to main app
                window.location.href = '/';
            }
        }, 3000);
    </script>
</body>
</html>
```

Key notes:
- Authentication is required (requireAuth) because only logged-in users should reach this page.
- The Plaid Link SDK script MUST be included for OAuth completion to work.
- Pico CSS is included for consistent styling with the rest of the app.
- The page shows a loading indicator while Plaid processes the OAuth redirect.
- The 3-second timeout is a fallback -- normally Plaid Link handles the redirect seamlessly.
- This file must be served over HTTPS in production (Cloudflare Tunnel provides this).
