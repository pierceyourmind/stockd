<task type="auto">
  <name>Task 1: CSV parser with broker auto-detection</name>
  <files>api.php</files>
  <action>
Add a `parseCSV(string $csvContent): array` function to api.php that:

1. **Auto-detects broker format** by examining the first few lines of the CSV:
   - **Fidelity**: First data row has 16 columns. Header row contains "Account Name/Number" as first column. No metadata lines before header.
   - **Schwab**: Has metadata lines before data. Contains section headers like "Brokerage" or account names followed by data rows with 26 columns. Look for lines starting with a quoted account section header pattern.

2. **Fidelity parser** (`parseFidelityCSV`):
   - Fidelity CSV columns (16): Account Name/Number, Symbol, Description, Quantity, Last Price, Last Price Change, Current Value, Today's Gain/Loss Dollar, Today's Gain/Loss Percent, Total Gain/Loss Dollar, Total Gain/Loss Percent, Percent Of Account, Cost Basis Total, Average Cost Basis, Type, Lot Date
   - Extract: symbol (col 1), company_name from Description (col 2), shares from Quantity (col 3), purchase_price from Average Cost Basis (col 13), account from Account Name/Number (col 0)
   - Account name: Use the full "Account Name/Number" value as the account name (e.g., "ROTH IRA - Z12345678"). Prefix with "Fidelity " so accounts display as "Fidelity ROTH IRA - Z12345678".
   - Skip rows where Symbol is empty, contains "Pending Activity", or equals cash-like entries (symbol is blank, or Description contains "CASH" or "FCASH" or "SPAXX" or "FDRXX" or similar money market fund tickers).
   - The last row often contains account totals — skip rows where Symbol is empty.

3. **Schwab parser** (`parseSchwabCSV`):
   - Schwab CSV has a metadata header (first 1-2 lines like "Positions for All-Accounts as of ..."), then section headers per account (e.g., "Brokerage  XXXX-1234" on its own line), then column headers, then data rows with 26 columns, then section totals.
   - Data columns (26): Symbol, Description, Quantity, Price, Price Change $, Price Change %, Market Value, Day Change $, Day Change %, Cost Basis, Gain/Loss $, Gain/Loss %, Ratings, Reinvest Dividends?, Reinvest Cap Gains?, % Of Account, Security Type, ... (remaining columns vary)
   - Extract: symbol (col 0), company_name from Description (col 1), shares from Quantity (col 2), account from the section header line preceding the data.
   - For purchase_price (cost basis per share): Schwab provides total "Cost Basis" (col 9). Calculate per-share cost: Cost Basis / Quantity. If Quantity is 0 or null, set purchase_price to null.
   - Account name: Use the section header text, prefixed with "Schwab " (e.g., "Schwab Brokerage XXXX-1234").
   - Skip rows where Symbol is empty, equals "Account Total", "Cash & Cash Investments", or where Quantity is 0/empty (cash positions).
   - Skip rows that are section totals or summary lines.

4. **Numeric cleaning** (`cleanNumeric` helper):
   - Strip `$`, `,`, `%`, `+` characters from numeric strings
   - Convert `--`, `n/a`, `N/A`, empty string to null
   - Return float value or null

5. **Return format**: Array with keys:
   ```php
   [
     'broker' => 'fidelity' | 'schwab',
     'holdings' => [
       [
         'symbol' => 'AAPL',
         'company_name' => 'APPLE INC',
         'shares' => 10.5,
         'purchase_price' => 150.25,  // cost basis per share
         'account' => 'Fidelity ROTH IRA - Z12345678',
       ],
       ...
     ],
     'skipped' => ['SPAXX (money market)', ...]  // human-readable skip reasons
   ]
   ```

6. **Error handling**: If CSV cannot be parsed or broker not detected, return `['error' => 'description']`.

Place helper functions (`cleanNumeric`, `parseFidelityCSV`, `parseSchwabCSV`) ABOVE the `parseCSV` function. Place `parseCSV` above the routing match statement. All functions should be pure (no database access, no side effects) — they just transform CSV text into structured data.

<task type="auto">
  <name>Task 2: Import CSV API endpoint with upsert logic</name>
  <files>api.php</files>
  <action>
Add an `importCSV(PDO $pdo): never` function to api.php and register it in the routing match statement as `'importCSV' => importCSV($pdo)`.

The endpoint:

1. **Accepts multipart file upload** via `$_FILES['csv_file']`:
   - Validate file exists and has no upload errors
   - Validate file size (max 5MB — CSV files are small)
   - Read file contents via `file_get_contents($_FILES['csv_file']['tmp_name'])`

2. **Parse CSV** by calling `parseCSV($csvContent)`:
   - If parseCSV returns an error, return 400 with the error message

3. **Upsert holdings** into the stocks table:
   - For each holding in the parsed results:
     - Check if a stock with the same `symbol` AND `account` already exists: `SELECT id FROM stocks WHERE symbol = ? AND account = ?`
     - If exists: UPDATE the existing record's `shares`, `purchase_price`, `company_name`, and `updated_at`
     - If not exists: INSERT new stock with `symbol`, `company_name`, `account`, `purchase_price`, `shares`, `is_watchlist = 0`
   - Track counts: `created`, `updated`, `skipped`
   - Wrap all inserts/updates in a transaction (`$pdo->beginTransaction()` / `$pdo->commit()`) for atomicity

4. **Return response**:
   ```php
   jsonResponse([
     'import' => [
       'broker' => 'fidelity',
       'created' => 5,
       'updated' => 2,
       'skipped' => ['SPAXX (money market)', 'FCASH (money market)'],
       'total_holdings' => 7,
       'accounts' => ['Fidelity ROTH IRA - Z12345678', 'Fidelity INDIVIDUAL - X98765432'],
     ],
     'message' => 'Successfully imported 7 holdings (5 new, 2 updated)'
   ], 201);
   ```

5. **Error handling**:
   - No file uploaded: 400 "No CSV file uploaded"
   - File too large: 400 "File too large (max 5MB)"
   - Parse error: 400 with parse error message
   - Database error: 500 with error message, rollback transaction

Place the `importCSV` function near the other CRUD functions (after `deleteStock`, before `getQuote`). Add the route entry in the match statement.

Note: The existing `purchase_price` column in the stocks table is being repurposed to store cost basis per share from the CSV. This is semantically correct — the purchase price IS the cost basis per share. The frontend already uses `purchase_price` for gain/loss calculations, so imported stocks will automatically show correct gain/loss with no frontend changes needed for COST-01.
