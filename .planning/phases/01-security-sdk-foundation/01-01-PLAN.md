  <action>
Create the auth/ directory and three files inside it.

**auth/session.php** -- Session configuration and guard function:
- Start with `declare(strict_types=1);`
- Call `session_start()` with secure cookie flags: `cookie_lifetime => 0`, `cookie_secure => true`, `cookie_httponly => true`, `cookie_samesite => 'Strict'`, `cookie_path => '/'`
- Define `requireAuth(): void` that checks `$_SESSION['authenticated'] === true`. If not authenticated: for API requests (check if `$_SERVER['CONTENT_TYPE']` contains `application/json` OR `$_GET['action']` is set), return HTTP 401 JSON `{"error": "Authentication required"}`; for page requests, `header('Location: /auth/login.php')` then `exit`
- Inside requireAuth(), regenerate session ID every 15 minutes using `$_SESSION['regenerated_time']` and `session_regenerate_id(true)` per the research pattern
- Define `isAuthenticated(): bool` that returns whether the session is valid (for use in login.php to skip login if already authenticated)

**auth/login.php** -- Login form and handler:
- Load phpdotenv to read .env (this file needs `require __DIR__ . '/../vendor/autoload.php'` and Dotenv -- but Composer is not installed yet in Wave 1). IMPORTANT: Since Composer is installed in Plan 02, this file must work WITHOUT Composer autoload initially. Read AUTH_PASSWORD_HASH directly from `$_ENV` and add a fallback: if `$_ENV['AUTH_PASSWORD_HASH']` is not set, check if a .env file exists and parse AUTH_PASSWORD_HASH from it manually using `parse_ini_file(__DIR__ . '/../.env')` or a simple `file()` + `explode()` approach. Add a comment: `// After Plan 02 installs Composer, this will use vendor/autoload.php + phpdotenv`
- ACTUALLY, simpler approach: Use a bootstrap include pattern. Create the login.php to `require_once __DIR__ . '/../bootstrap.php'` where bootstrap.php will handle .env loading. For now in this plan, create a minimal bootstrap.php that reads .env manually. Plan 02 will upgrade it to use Composer autoload + phpdotenv.
- **Revised approach for bootstrap.php:** Create `bootstrap.php` in project root. It reads `.env` line by line, parses KEY=VALUE pairs (skip comments starting with #, skip empty lines, trim whitespace), and sets them into `$_ENV`. This is a temporary .env loader that Plan 02 will replace with phpdotenv. Keep it simple -- no variable interpolation, no quote handling needed for our values.
- Include `auth/session.php` at the top
- If already authenticated (via `isAuthenticated()`), redirect to `/index.php` and exit
- On POST: get `$_POST['password']`, call `password_verify()` against `$_ENV['AUTH_PASSWORD_HASH']`. On success: `session_regenerate_id(true)`, set `$_SESSION['authenticated'] = true`, set `$_SESSION['regenerated_time'] = time()`, redirect to `/index.php`, exit. On failure: set `$error = 'Invalid password'`
- Render a minimal login form using Pico CSS (match app's dark theme). Include the same Pico CSS CDN link as index.php. Show a centered card with "Stockd" heading, password input field (autofocus, required), submit button "Login", and error message display (red text) if `$error` is set. Use `data-theme="dark"` on the html tag to match the app's dark theme. Style it to look clean and match the existing app aesthetic.

**auth/logout.php** -- Session teardown:
- Include `auth/session.php` (which calls session_start)
- Call `$_SESSION = []`, then `session_destroy()`
- If session cookie exists, clear it with `setcookie()` using empty value and past expiry
- Redirect to `/auth/login.php` and exit

**bootstrap.php** (project root) -- Minimal .env loader (temporary):
- Read `.env` file from `__DIR__ . '/.env'`
- If file doesn't exist, skip silently (app will fail gracefully when AUTH_PASSWORD_HASH is missing)
- Parse line by line: skip empty lines, skip lines starting with `#`, split on first `=`, trim key and value, strip surrounding quotes from value if present, set into `$_ENV[$key]`
- Add a clear comment at top: `// Temporary .env loader -- replaced by phpdotenv in Plan 02`

- Add `require_once __DIR__ . '/bootstrap.php';` as the FIRST line after `declare(strict_types=1);` (before the Content-Type header)
- Add `require_once __DIR__ . '/auth/session.php';` immediately after bootstrap
- Call `requireAuth();` immediately after the require -- this must come BEFORE the CORS headers and before any JSON output. HOWEVER, the OPTIONS preflight request must still work without auth (browsers send OPTIONS before POST). So: keep the OPTIONS check where it is (lines 9-12), and add the auth check AFTER the OPTIONS handler. The order should be:
  1. `declare(strict_types=1);`
  2. `require_once __DIR__ . '/bootstrap.php';`
  3. `require_once __DIR__ . '/auth/session.php';`
  4. CORS headers (Content-Type, Access-Control-Allow-*)
  5. OPTIONS handler (return 200 and exit)
  6. `requireAuth();`
  7. Rest of api.php (database setup, routing, etc.)

**index.php** -- Add auth requirement at the very top, before any HTML output:

  ```php
  requireAuth();
  ?>
  ```
- This must be the FIRST thing in the file. No whitespace before `<?php`.
- The existing `<!DOCTYPE html>` follows immediately after `?>`.
